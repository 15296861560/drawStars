## 一、需求背景与目标

### 1.1 背景

任务管理体系（PC，v1.0 P0–P9）已完整落地：任务设计、任务大厅（用户侧）、生命周期管理、审核流程、奖励发放、统计看板与通知体系；移动端统一平台（uni-app 壳）也已具备模块分发、Ticket 免登、Bridge 端能力、消息中心等底座能力。但任务的**高频动作仍被锁在 PC 上**：

- **用户侧**：领取、完成、领奖等高频动作发生在通勤、排队等碎片化场景；拍照留证、扫码、定位打卡等完成方式天然依赖手机能力，PC 无法闭环
- **发布侧**：运营人员离开工位即"失明"——无法随时发布活动任务、无法查看实时数据、无法催办拖延的执行者
- **审核侧**：任务发布审核与完成凭证审核积压时，审核者无法利用碎片时间处理，审核时效直接影响任务上线与用户领奖体验
- **平台侧**：PC 管理端「任务概览 / 任务列表 / 任务审核」已具备完整能力，但缺少移动化的消费视图与应急处理入口

本期在移动端统一平台内建设**任务大厅模块（task.mobile）**，将 PC 端任务概览、任务列表、任务审核集成进来，并围绕**发布、领取、完成**三大核心动作做移动化体验重塑，让任务"随时随地可发、可领、可完成、可审"。

### 1.2 设计目标

| 目标           | 说明                                                                            |
| -------------- | ------------------------------------------------------------------------------- |
| **移动闭环**   | 发布、领取、完成、审核四类核心动作全部移动化闭环，不强制回跳 PC                 |
| **一键高效**   | 高频操作降步长：每日任务一键接取/一键领奖、卡片式审核、批量操作、快捷指派       |
| **用好手机**   | 拍照凭证、扫码接任务、定位打卡、系统分享，把手机能力变成任务完成方式            |
| **与 PC 同源** | 复用同一套任务数据、状态机与权限码（`system:task:*`），移动端**不建第二套规则** |
| **壳深度集成** | Ticket 免登、消息角标、深链直达、Bridge 能力按端降级（对齐移动端统一平台 4.12） |
| **低门槛发布** | 模板化分步向导，移动端 1 分钟发一个任务；复杂配置智能引导回 PC                  |

### 1.3 不在本期范围

| 项                             | 说明                                                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 任务交易市场 / 悬赏 / 多人协作 | 与《任务管理体系 PRD》1.3 保持一致，两端均不做                                                                                  |
| 原生重写                       | 本模块为 H5 模块，不做原生页面（对齐移动平台 1.3）                                                                              |
| 完整报表能力                   | 自定义报表、多维交叉分析、大数据导出仍留在 PC；移动端仅做核心指标、趋势与预警                                                   |
| 推送全通道                     | 厂商推送 / APNs / 小程序订阅消息跟随移动端统一平台 v1.1 推送节奏                                                                |
| 小程序离线                     | 小程序端仅在线打开（对齐移动平台 D08 / 1.4.2），不承诺离线                                                                      |
| 移动端复杂任务编辑             | 组合条件（COMPOSITE）、实物奖励库存/物流配置等复杂编辑引导至 PC 完成（v1.1 评估扩展）                                           |
| 任务分类 / 奖励模板管理        | 维持 PC 管理端（`taskManage/categories`、`taskManage/templates`），移动端仅消费                                                 |
| 「去完成」站内跳转全量覆盖     | LEARN（课程）、CONTENT（内容创作）等条件类型平台暂无对应移动端模块，v1.0 降级为图文指引（映射表见 4.1.3）；待目标模块上线后接入 |

### 1.4 v1.0 范围分级（P0 / P1 / P2）

> 原则与移动端统一平台 1.6 对齐：P0 为上线必达，P1 同迭代尽力，P2 可顺延 v1.1+。四端策略：**App + H5 为 P0 参考实现**，小程序 P0 冒烟、P1 对齐。

| 优先级         | 范围                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **P0（必达）** | 模块接入壳（manifest / 权限声明 / 发布门禁）；任务大厅（分类/筛选/搜索/排序）；任务详情与接取；自动条件任务进度同步；**凭证提交（拍照 + 文字）**；我的任务（五状态）；奖励领取（含实物地址填写）；**每日任务包一键接取/一键领奖**；**快捷发布（模板分步向导，复杂配置引导 PC）**；**审核中心（任务发布审核 + 凭证审核，含批量通过）**；任务管理（列表/生命周期操作/数据快照）；任务概览（核心指标 + 预警）；消息通知（复用通知表）与待办角标接口；模块设置（通知偏好，见 7.8） |
| **P1（尽力）** | 扫码接任务；一键催办；快捷指派（通讯录/最近联系人）；审核快捷语；任务分享卡片；定位打卡凭证；到期日历订阅；排行榜；成就墙移动化                                                                                                                                                                                                                                                                                                                                                |
| **P2（顺延）** | 语音输入；移动端任务编辑；报告导出推送；桌面小组件；离线缓存强化；AI 任务推荐                                                                                                                                                                                                                                                                                                                                                                                                  |

## 二、用户角色

| 角色                 | 移动场景                                     | 核心诉求                       |
| -------------------- | -------------------------------------------- | ------------------------------ |
| **普通用户（玩家）** | 通勤/碎片时间刷任务、拍照完成、领奖          | 快、爽、奖励明确、进度实时     |
| **任务发布者**       | 随时随地发布活动任务、看实时数据、催办执行者 | 快速发布、随时掌控、触达执行者 |
| **任务审核者**       | 碎片时间处理审核积压（任务发布 + 完成凭证）  | 高效、批量、不漏审、驳回有据   |
| **平台管理员**       | 移动看板监控、异常预警、应急下架             | 全局掌控、应急处理、可审计     |

**权限控制**（复用 PC 权限码，不新增平行体系）：

| 权限码                | 控制的移动端能力                                                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| —（public + 登录）    | 任务大厅、任务详情、接取/完成/领奖、我的任务（模块入口对全体登录用户可见）                                                                                       |
| `system:task:list`    | 「概览」Tab、「管理」Tab（任务列表与数据快照）                                                                                                                   |
| `system:task:create`  | 中央「+」发布入口、快捷发布向导（含 Step1「复制历史任务」起点数据源 `publish/my-tasks`，见 7.3）、复制任务                                                       |
| `system:task:status`  | 任务暂停/恢复/下线操作                                                                                                                                           |
| `system:task:audit`   | 「审核」Tab（任务发布审核 + 凭证审核）                                                                                                                           |
| `system:task:assign`  | 快捷指派                                                                                                                                                         |
| `system:task:claim`   | 本期不映射任何移动端能力；被指派用户的确认接取仅做数据归属校验（assignment 被指派人 = 当前用户），不要求持码，「已指派」Tab 对全体登录用户可见，避免全员预配权限 |
| `system:task:operate` | 一键催办等运营动作                                                                                                                                               |
| `system:task:update`  | 提交审核（7.3 `publish/submit`，对齐 PC 8.3「编辑任务、提交审核」归口，免审直达同走该接口）；v1.1「移动端基础编辑」评估时扩展编辑类能力（复杂编辑仍引导 PC）     |

> 控制方式对齐移动端统一平台 4.5「三层控制」：入口层（Tab/按钮显隐）+ 操作层（前端隐藏 + 后端 `@RequirePermissions` 强校验）+ 数据层（BFF 按权限裁剪返回字段）。**模块 manifest 声明 `permissionCodes: []` 并标记 public+登录**，管理类 Tab 与按钮由权限码动态渲染。

## 四、各模块详细设计

> **总原则**：所有业务规则（任务类型、条件注册表、奖励类型、生命周期状态机、分配方式、防刷策略）**以《任务管理体系 PRD》第四章为准**，本章只定义移动端的**交互形态、裁剪范围与新增能力**，不重复定义也不允许分叉。涉及 PC 已定义规则的处仅引用章节号。

### 4.1 任务大厅（用户侧）

#### 4.1.1 大厅结构（自上而下）

| 区块           | 内容                                                          | 说明                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 顶部搜索栏     | 关键词搜索任务标题/描述                                       | 防抖 300ms；历史关键词本地缓存                                                                                                                                            |
| 每日任务包卡片 | 今日完成度（3/8）+ 一键接取/一键领奖按钮                      | 详见 4.1.4；无可接任务时隐藏                                                                                                                                              |
| 分类 Tab       | 全部 / 日常 / 活动 / 成就 / …（读 `task_category`）           | 横向滚动；记忆上次选择                                                                                                                                                    |
| 状态/排序筛选  | 状态：可接取/进行中/待领奖；排序：推荐/奖励最高/最新/即将过期 | 抽屉式筛选面板。ASSIGNED 定向任务仅对被指派人可见（PC 4.1.7）：**待确认时不在大厅**（归「已指派」Tab，见 4.4），确认接取创建实例后按进行中/待领奖正常参与大厅筛选与卡片流 |
| 任务卡片流     | 无限滚动（默认 20 条/页）                                     | 下拉刷新                                                                                                                                                                  |

#### 4.1.2 移动端任务卡片（较 PC 增强）

| 倒计时                            | 限时任务显示剩余时间（< 24h 变橙色，< 1h 变红并呼吸闪烁）                                                                                                 |
| 主操作按钮                        | 卡片右下角常驻：`接取` / `去完成` / `领取奖励` / `已过期` / `确认接取`（指派待确认态，见 4.4「已指派」Tab），**免进详情页直接操作**（本模块核心体验差异） |
| 子任务角标                        | "含 3 个子任务"                                                                                                                                           |
| 指派标记                          | 定向指派任务显示"指派"角标                                                                                                                                |

#### 4.1.3 任务详情页

| 区块           | 说明                                                                   |
| -------------- | ---------------------------------------------------------------------- |
| 头部           | 图标/标题/编号 taskNo/分类/难度/倒计时                                 |
| 奖励区         | 奖励组合展示（复用 PC 奖励类型渲染）                                   |

| 子任务树       | 树形/时间轴展示，顺序解锁模式高亮"当前步骤"                            |
| 底部吸底操作栏 | `立即接取` / `去完成`（跳转规则见下方映射表）/ `提交凭证` / `领取奖励` |
| 分享按钮       | P1，见 4.10.2                                                          |

| 条件类型（PC 4.1.3）               | 站内目标           | v1.0 移动端跳转方式                                                                                                                                                                                                                                                                                                                                                                                                                  | 完成判定               |
| ---------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------- |
| SURVEY 完成问卷                    | 指定问卷填写页     | **v1.0 降级图文指引**（展示问卷标题与填写方式，链接文本可复制）：问卷系统为响应式 H5（公开填写路由 `/home/homepage/survey/fill/:shareCode`），**非壳内页面**——`navigate` 仅支持壳内路由/深链、平台 Bridge v1.0 无打开外部 URL 能力（平台 4.12.2，小程序 web-view 另受域名白名单限制）。直接打开填写页依赖平台后续扩展（`openUrl` 类 Bridge），就绪后由详情接口 `goto` 字段（见 7.1）按 `condition_config.survey_id` 解析返回目标地址 | 问卷提交事件回流       |
| SHARE 分享                         | 无目标页（动作型） | 直接发起 Bridge `share`（见 4.10.2，**P1**；P1 上线前降级图文指引）                                                                                                                                                                                                                                                                                                                                                                  | 分享事件由后端回流判定 |

### 4.2 任务完成与凭证提交

#### 4.2.1 两种完成路径

| 路径     | 说明                                               | 移动端体验                                           |
| -------- | -------------------------------------------------- | ---------------------------------------------------- |
| 自动判定 | 登录/消费/浏览等事件驱动（PC 4.1.3 条件注册表）    | 进度实时更新；达标后卡片状态自动变"待领奖"+ 推送通知 |
| 凭证提交 | 需人工确认的完成内容（截图、线下消费小票、作品等） | **移动端为主要提交入口**：拍照 + 文字说明            |

> **凭证粒度边界**：v1.0 凭证为**任务级**（一个 `task_instance` 一条有效 submission，整体提交/整体审核）；含多个子任务且各子任务均需凭证的场景不支持，子任务级凭证留待 v1.1+ 评估。子任务仅需**最终凭证**的任务（末节点提交一次）不受影响。

#### 4.2.2 凭证提交表单

| 字段     | 类型                | 必填       | 说明                                                                                                                |
| -------- | ------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------- |
| 图片凭证 | 按任务配置 X～Y 张  | 按任务配置 | 张数下限/上限取自 `evidence_image_min/max`（缺省 1～9）；Bridge `chooseImage`（拍照/相册）；单张 ≤ 10MB；压缩后上传 |
| 文字说明 | ≤ 500 字            | 按任务配置 | 可描述完成情况                                                                                                      |
| 扫码记录 | 系统生成            | —          | 若经"扫码接任务"进入，自动附扫码时间，落 `evidence.scan_at`（见 5.2）（P1）                                         |
| 位置信息 | 经纬度 + 逆地理解析 | 按任务配置 | Bridge `getLocation`（P1）；用于 LBS 打卡类任务                                                                     |

> 任务设计侧新增**提交要求配置**（PC 任务表单同步扩展，字段存于 `task.condition_config`）：`{ "evidence_required": true, "evidence_image_min": 1, "evidence_image_max": 9, "evidence_text": false, "evidence_location": false }`。**缺省值**（未显式配置时）：`evidence_required` / `evidence_text` / `evidence_location` 均 `false`——默认无凭证要求，任务走自动判定路径；上方及 5.3 的 JSON 示例为**显式开启**凭证（required=true）的非缺省配置（仅 `evidence_text`/`evidence_location` 取值与缺省一致）。**生效优先级**：`evidence_required` 主导——为 `false` 时整个提交要求配置（`evidence_image_min/max`、`evidence_text`、`evidence_location`）均不生效（即缺省任务不因 `image_min` 缺省为 1 而强制图片）；为 `true` 时图片张数要求生效（`evidence_image_min`/`evidence_image_max` 缺省 1～9，`min ≥ 1` 即强制图片、`min = 0` 图片可选）；`evidence_max_round` 缺省 3（见 4.2.3）。PC PRD 数据模型不变更表结构，仅扩展 JSON 语义。

#### 4.2.3 凭证审核状态机（新增，移动端主推）

```text
未提交 ──提交凭证──► 待审核(PENDING) ──审核通过──► 已通过(APPROVED)
                          │                        │
                          │                        └──触发 instance → COMPLETED（进入待领奖）
                          │
                          ├──驳回(REJECTED) ──用户修改后重新提交──► 待审核(PENDING)
                          │        │
                          │        └──重提轮数耗尽（submit_round ≥ evidence_max_round）──► 实例转 FAILED（不可再提交）

任务过期/下线 ──► 已失效(EXPIRED)（不可再提交与审核）
```

**submission 状态与 `task_instance` 状态联动**（instance 状态机对齐 PC 5.1：ACCEPTED / IN_PROGRESS / SUBMITTED / COMPLETED / FAILED / EXPIRED）：

| submission 动作        | instance 状态变化           | 说明                                                                                                                                                                           |
| ---------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 提交凭证（→ PENDING）  | `IN_PROGRESS` → `SUBMITTED` | 写 `submitted_at`；**与 PC 6.1 `/api/tasks/:id/submit` 为同一链路**，落库即新增 `task_submission` 记录（PC 端提交同样写本表，两端数据同源）                                    |
| 审核通过（→ APPROVED） | `SUBMITTED` → `COMPLETED`   | 写 `completed_at`，进入待领奖                                                                                                                                                  |
| 审核驳回（→ REJECTED） | `SUBMITTED` → `IN_PROGRESS` | 用户可修改后重提；**末轮驳回**（`submit_round ≥ evidence_max_round`）时实例不回 `IN_PROGRESS`、直接转 FAILED，用户侧归入「我的任务 → 已过期」（原因=凭证驳回轮次耗尽，见 4.4） |
| 失效（→ EXPIRED）      | instance 保持原状态         | 仅 submission 置 EXPIRED；instance 自身的 EXPIRED 由 PC 既有机制判定，见下方"失效判定"                                                                                         |

| 规则         | 说明                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 重提次数     | 取任务配置 `evidence_max_round`，语义为**允许的最大提交轮数**：`submit_round` 从 1 起计（首次提交 = 1）；驳回时若 `submit_round ≥ evidence_max_round` 则不可再提、实例转 FAILED；**缺省 = 3**（未显式配置时按 3 轮执行：首提 + 2 次重提，作为防滥用与审核工作量基线；如需更多轮次由发布侧在 `condition_config` 显式配置更大值）；0/1 = 仅允许首轮提交（驳回即终结）；每次重提生成新 submission 记录，保留历史 |
| 驳回必填理由 | 复用审核快捷语或手写，用户在"我的任务"实例详情可见驳回原因                                                                                                                                                                                                                                                                                                                                                    |
| 幂等         | 同一实例同一时刻仅允许一条 PENDING（DB 唯一索引，见 5.2）；审核接口携带 `version` 乐观锁防并发双审（载体定义与原子更新规则见 5.2，version 冲突返回 409）                                                                                                                                                                                                                                                      |
| 时效         | 凭证提交受任务 `end_time` 与接取有效期约束；过期后提交入口置灰并提示                                                                                                                                                                                                                                                                                                                                          |
| 失效判定     | **仅指 submission 的失效**：不设主动定时扫描，采用惰性判定——提交/重提/审核动作时校验任务 `end_time`、任务状态（OFFLINE）与接取有效期，命中则 submission 置 EXPIRED、instance 保持原状态；审核列表对存量 PENDING 二次校验兜底。instance 自身的 EXPIRED（任务到期/下线回收）由 PC 既有机制判定                                                                                                                  |

#### 4.5.3 提交结果

- 步骤暂存（向导内）仅存本地 Storage，不产生服务端草稿；保存草稿落服务端（见 7.3），提示"可在 PC 任务列表继续编辑"。H5 端为浏览器 localStorage（弱安装在线态，清缓存/隐身模式不可靠），离开向导时引导「保存草稿」落服务端，避免本地暂存丢失
- **草稿取回边界**：v1.0 移动端**不提供草稿列表与再编辑入口**——保存的草稿仅可在 PC 任务列表继续编辑（7.3 不提供草稿查询接口，向导每次进入均为全新创建，Step1 无「我的草稿」起点）。**权限组合边界**：PC 任务列表入口需 `system:task:list`，仅有 `system:task:create`（无 list，见二章权限表）的用户保存的服务端草稿在 PC 端无取回路径——移动端检测到当前用户无 list 权限时，点「保存草稿」需先提示「草稿仅可在 PC 端任务列表继续编辑，当前账号无该入口权限；草稿将保留，待权限开通后取回，或请完成本次发布」，确认后方可保存（本地步骤暂存不受影响，见上条）；移动端基础编辑（含草稿续编）随 v1.1 评估（见 4.10.5）
- 提交审核 → 进入 PC 审核流（本模块审核中心可审）；WebSocket 通知审核者
- 直接上线（有权限且配置免审）→ 立即在大厅可见，创建者收到上线成功通知
- 发布结果页 `/publish/result/:taskId` 以 taskId 定位具体任务（展示结果与后续引导）；后续审核结果通知深链同样携 taskId 落该页（见 4.9.3）

### 4.9 消息与待办集成

#### 4.9.1 通知场景（复用 PC 4.6 全量场景 + 新增）

| 新增场景                              | 触发时机                                     | 通知对象                                                                                          |
| ------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `TASK_URGE` 催办                      | 发布者一键催办                               | 未完成用户                                                                                        |
| `SUBMISSION_REJECTED` 凭证被驳回      | 审核者驳回凭证（**文案按轮次分流**，见下注） | 提交用户                                                                                          |
| `SUBMISSION_APPROVED` 凭证审核通过    | 审核者通过凭证                               | 提交用户（奖励进入待领取）                                                                        |
| `SUBMISSION_AUDIT_PENDING` 新凭证待审 | 用户提交凭证                                 | 按 4.7.3 凭证审核人分配规则（任务发布审核人/审核角色；未配置时广播 `system:task:audit` 持有角色） |
| `TASK_AUDIT_PENDING` 新任务待审       | 创建者提交审核                               | 审核者（同上）                                                                                    |

> **催办与到期通知的关系**：`TASK_EXPIRING`（PC 4.6 已有，系统自动、到期前定时触发）与 `TASK_URGE`（发布者主动触发）相互独立、互补不替代；同一自然日内对同一用户两者都命中时，服务端**合并为一条**（以催办文案为准），避免重复打扰。
>
> **`SUBMISSION_REJECTED` 文案按轮次分流**：驳回时比较 `submit_round` 与 `evidence_max_round`——可重提（`submit_round < evidence_max_round`）→ 常规驳回文案（含「查看驳回理由并修改重提」引导）；重提轮数耗尽（实例已转 FAILED，见 4.2.3）→ 终结文案（「重提次数已用尽，任务未通过、不可再提交」），**不出现可重提引导**。两种文案的通知深链均落实例详情（历史凭证与驳回理由可查；FAILED 实例归入「我的任务 → 已过期」，见 4.4）。

通知下发链路、模板、偏好设置完全复用 PC 4.6（WebSocket + 站内信），通知点击通过深链落回本模块对应页面。

```text
  ?path=/manage/detail/123             ← 任务管理详情（催办/指派入口）
  ?path=/overview                      ← 概览
  &source=scan|share|notify          ← 来源标记（埋点用；扫码接取统一归 scan，见 4.10.1 码内容）
```

> **解析约定**：`path` 值内部允许再带一个 `?`（Tab/查询参数，如 `/my?tab=pendingReward`），解析时以**首个 `?` 为界**——其前为路由路径、其后为路由查询串；`path` 值本身不做 URL 编码，跨系统拼接时由调用方负责整段合法。

深链落地遵循移动平台 4.8.4：未装（App）→ 详情页引导安装后打开；无权限 → 缺权提示。

### 9.2 模块接入步骤（对齐移动平台 9.2）

1. 按平台 manifest 规范打包（`moduleCode: task.mobile`，platforms 四端，`permissionCodes: []` 标记 public+登录，`bridgePermissions: chooseImage, scanQRCode, getLocation, share, navigate, saveImage, writeCalendar`——后两项需平台扩展 Bridge API，未就绪时先从清单裁剪再发版，见 4.11 注与下方 manifest 示例）
2. 实现 Ticket 换票与 Bridge 协议（含降级处理）
3. 在 **drawStars-Vue3** 应用管理创建模块：上传 zip、配置 `module_url`、过发布门禁（平台 4.12.3）
4. 后端上线 `/api/mobile/tasks*` BFF 与 `task_submission` 等增量表
5. 工作台/消息中心配置任务待办聚合入口（**壳工作台聚合能力依赖平台 v1.1，见 4.9.2**；v1.0 仅需打通消息中心通知深链，待办聚合入口随平台 v1.1 上线后配置）
6. 埋点：`module_open_task_mobile` 为平台预置模块打开事件（随模块接入自动上报，见 9.4 注）+ 第九章事件字典最小集
