> **项目**: drawStars (Vue3)
> **版本**: v1.0
> **日期**: 2026-08-08

## 一、需求背景与目标

### 1.1 背景

drawStars 工具模块已存在聊天室演示页（`/home/toolHomePage/chat`，历史基于第三方 RTM，仅作交互参考），尚未形成可运营、可扩展的即时通信（IM）产品体系。本期明确 **消息、会话、关系链、房间/群、实时推送全部自研**，能力设计可参考 TIM/声网，但 **产品运行时不依赖其 SDK/云服务**。目标如下：

- **实时社交沟通（基础）**：多用户同步交流，打破地域限制，即时传递信息，满足聊天、倾诉、结识他人的需求
- **聚集同好、建立社群归属感**：按兴趣/话题/身份汇聚用户，围绕共同话题讨论，形成圈子与认同感
- **信息交换与观点交流**：主题讨论、见闻分享、答疑与经验交流
- **娱乐与情绪消遣**：闲聊、互动玩法、连麦陪伴，提供情绪释放与陪伴体验
- **平台活跃与留存**：拉长停留时长，提升活跃度与留存；支撑数据分析与历史记录查询
- **可扩展**：预留审核、机器人、直播互动、客服等后续能力接入点

### 1.2 设计目标

| 目标           | 说明                                                                 |
| -------------- | -------------------------------------------------------------------- |
| **即时可达**   | 在线消息秒级送达；离线可漫游/推送（分版本落地）                      |
| **能力完整**   | 覆盖 TIM 核心域：账号、会话、消息、关系链、群组/房间、资料、状态     |
| **场景分层**   | 同时支持单聊、群聊、主题房间/聊天室、社群（超大群预留）              |
| **社群运营**   | 话题、公告、成员角色、禁言/踢出等运营治理能力                        |
| **可观测**     | 消息/活跃/留存指标可统计；管理端可检索历史与审计                     |
| **安全可控**   | 鉴权、敏感词、举报、黑名单、频率限制与内容审核策略                   |
| **全自研可控** | 实时通道、消息存储、治理与统计均在自有技术栈内，不绑定第三方 IM SaaS |
| **体验统一**   | 与平台用户体系、权限、通知、积分打通，避免「孤岛 Demo」              |

| 企业级客服坐席路由系统                | 客服场景能力包 v2.0+                                 |

### 1.4 关键决策：全自研实现方案

> **v1.0 结论**：**不接入声网 / 腾讯云 IM 等第三方 IM SDK 或云通道**。实时通信采用 **自研 WebSocket 网关 + 业务消息服务 + 自建库**；TIM/声网文档仅用于能力对标与验收参考。历史 Demo 页可保留为实验室对照，**正式链路与其脱钩**。

#### 1.4.1 逻辑架构

```
[Web 客户端]
    |  HTTPS（REST：鉴权/资料/历史/治理/上传）
    |  WSS  （长连接：推送/轻量信令；发送也可走 REST）
    v
[API Gateway]
    ├─ ImAuth / Token
    ├─ ImRestApi（会话、消息发送、房间/群、关系链、管理端）
    └─ ImWsGateway（连接管理、订阅、推送、心跳）
           |
           v
    [ImMessageService] ──落库/分配 seq──► MySQL（权威数据）
           |
           ├── Pub/Sub（Redis，多实例扇出，单机可进程内总线）
           └── 在线路由表（userId → gatewayNode + connId）
```

#### 1.4.2 技术原则

| 原则             | 说明                                                                            |
| ---------------- | ------------------------------------------------------------------------------- |
| **库为权威**     | 一切可检索、可补洞、可审计的消息以 DB 为准；WS 只做在线推送                     |
| **先写后推**     | 发送必须先持久化成功再广播（见 4.4.0）                                          |
| **水平扩展**     | 多 Gateway 节点通过 Redis Pub/Sub 扇出；粘性会话非必须                          |
| **可参考不依赖** | 产品能力可对齐 TIM；实现与账单、SDK、Vendor Token 无关                          |
| **连麦预留**     | v1.1 音视频：自研信令 + 浏览器 WebRTC（SFU 可后期自建），**不引入声网 RTC SDK** |

#### 1.4.3 与第三方方案对比（决策说明）

| 维度       | 全自研（本期）        | 声网 RTM / 腾讯云 IM     |
| ---------- | --------------------- | ------------------------ |
| 数据与合规 | 消息与关系全在自有库  | 部分托管第三方           |
| 成本       | 自有机器与研发        | 按 DAU/峰值计费          |
| 能力完整度 | 按 PRD 自建，节奏可控 | 开箱快，深度定制受限     |
| 现有 Demo  | 仅 UI/流程参考        | 曾用 RTM，正式版废弃依赖 |

### 1.5 业务成功指标（产品侧）

| 指标              | v1.0 目标（上线 4 周后） | 统计口径                     |
| ----------------- | ------------------------ | ---------------------------- |
| IM DAU / 平台 DAU | ≥ 15%                    | 当日进入过 IM/房间或发过消息 |
| 人均房间停留      | ≥ 8 分钟                 | 进房到离房或心跳超时累加     |
| 次日回流率        | ≥ 25%                    | 当日活跃用户次日再次活跃     |
| 消息发送成功率    | ≥ 99%                    | 客户端成功 ACK / 尝试发送    |

## 四、各模块详细设计

### 4.1 账号与连接

#### 4.1.1 登录鉴权

| 功能           | 说明                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------- |
| 平台登录态绑定 | 必须先完成 drawStars 用户登录；IM `userId` 与平台 `userId` 一致（字符串化）                         |
| Access Token   | REST 鉴权凭证，后端签发，默认 **2 小时**，到期前 5 分钟可续签（`/api/im/token/refresh`）            |
| WS Ticket      | 连接 WebSocket 的短时票据，默认 **≤ 2 分钟**单次有效（`/api/im/ws-ticket`），不可当 REST Token 复用 |
| 登录成功       | 持 Access Token 调 REST；再换 Ticket 建连；拉取会话列表与各会话 `maxSeq`                            |
| 登出           | 断开 WS、失效 Token/Ticket；本地消息缓存可保留                                                      |
| 失效处理       | Access Token 自动续签一次；失败码 `IM_AUTH_EXPIRED`                                                 |

> **安全约束**：签名密钥仅存服务端；前端只持有 Access Token 与短时 WS Ticket。文档中 **不再使用 UserSig 命名**（避免与腾讯云 IM 混淆）。

#### 4.1.2 连接与在线状态

| 状态         | 说明                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| CONNECTING   | 建立连接中                                                             |
| CONNECTED    | 可收发推送；**即便 WS 断开，仍可用 REST 发消息**（先写后推，见 4.4.0） |
| RECONNECTING | 断线自动重连（指数退避：1s起，上限 30s，最多 10 次）                   |
| DISCONNECTED | 主动登出或重连耗尽                                                     |

用户呈现状态：`ONLINE` / `BUSY` / `INVISIBLE` / `OFFLINE`。
隐身对陌生人展示为离线；对好友是否可见 v1.1 可配。

#### 4.1.3 多 Tab 与连接策略（Web）

| 规则             | 说明                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| 单活跃连接       | 同一用户同一浏览器多 Tab，仅 1 个 Tab 持有实时连接                                               |
| 互踢信令         | 新 Tab 登录成功后广播 `IM_TAB_TAKEOVER`，旧 Tab 降级为「仅 UI，通过 storage 事件刷新」或提示刷新 |
| **连接心跳**     | WS Ping/Pong **25s** 一次；超时 **90s** 断开并重连（与房间停留心跳分离）                         |
| **房间停留心跳** | 在房期间 REST/WS `ROOM_PRESENCE` **30s** 一次；连续缺 **3** 次视为离房并结算停留时长             |

#### 4.1.3.1 会话/房间订阅与退订

| 场景                        | 行为                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------- |
| WS 连接成功                 | 客户端对「会话列表中未删除的 C2C/GROUP」批量 `SUBSCRIBE`；可分页，单次最多 100 个 `conversationId` |
| 打开某个会话窗              | 确保已订阅该 `conversationId`（幂等）                                                              |
| **进入房间成功**            | 服务端将该用户标记为 in-room，并 **自动订阅** 对应 ROOM 会话；客户端可再发 `SUBSCRIBE` 兜底        |
| **离开房间 / 停留心跳超时** | 服务端清除 in-room，并 **自动 UNSUBSCRIBE** 该 ROOM 会话推送；其后仅走离房未读规则（@）            |
| 大厅浏览未进房              | **不订阅** 房间消息，不接收该房 MESSAGE 推送                                                       |
| 删除会话                    | 客户端 `UNSUBSCRIBE`；服务端可忽略已删会话的推送                                                   |
| 重连成功                    | 重新订阅：会话列表 + 当前仍 in-room 的房间                                                         |

上行补充：`UNSUBSCRIBE { conversationIds: string[] }`。

#### 4.1.3.2 在线人数与路由表

| 项               | 规则                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------- |
| 连接路由         | Redis/内存：`userId → { nodeId, connId, tabId, lastSeen }`；互踢时覆盖旧映射                                |
| 用户在线         | 存在有效 WS 连接且连接心跳未超时 → `ONLINE`（隐身另计展示）                                                 |
| **房间在线人数** | 统计当前 `in-room` 且停留心跳未超时的去重 `userId`；**不是**「订阅了会话但未进房」的人数                    |
| 刷新             | Gateway/Presence 变更时更新；大厅展示允许 **≤ 15s** 延迟；接口可返回 `onlineCount` + `onlineCountUpdatedAt` |
| 多节点           | 各节点本地 in-room 集合经 Redis Set（`room:{id}:online`）汇总；成员进房 SADD、离房/超时 SREM                |
| 误差             | 允许短暂不一致；以 Presence 超时清理为准，不做强实时全局锁                                                  |

#### 4.1.4 断线补洞同步

重连成功后客户端对每个活跃会话执行：

```
GET /api/im/conversations/{id}/messages/sync?afterSeq={localMaxSeq}&limit=50
```

| 规则       | 说明                                                           |
| ---------- | -------------------------------------------------------------- |
| 缺口拉取   | 循环直到返回空或追上服务端 `maxSeq`                            |
| 去重       | `msgId` 优先，其次 `clientMsgId`                               |
| 发送中队列 | 本地 `PENDING` 消息在重连后按原 `clientMsgId` 重试，服务端幂等 |
| 会话列表   | 同步后刷新未读与最后一条消息                                   |

### 4.3 会话管理

| 功能      | 说明                                             |
| --------- | ------------------------------------------------ |
| 会话列表  | 按 `last_msg_time` 倒序；类型 C2C / GROUP / ROOM |
| 未读角标  | 见 4.3.1；群/房间「提及我」优先红点              |
| 置顶      | 每用户最多 20                                    |
| 删除会话  | 默认仅删入口；可选同时清空本地缓存               |
| 草稿      | 本地草稿，切换会话恢复                           |
| 标记/分组 | v1.1+                                            |

会话与业务主体映射：

| conv_type | biz_id 含义    | 目标表         |
| --------- | -------------- | -------------- |
| C2C       | 对方 `user_id` | 会话唯一键见下 |
| GROUP     | `group_id`     | `im_group`     |
| ROOM      | `room_id`      | `im_room`      |

**C2C 会话唯一键**：`pair_key = min(userIdA, userIdB) + '_' + max(userIdA, userIdB)`（字符串比较或数值比较规则固定为数值）。同一对用户全局仅一条 `conv_type=C2C` 会话。

#### 4.3.1 未读计数规则

服务端维护每用户每会话：`last_read_seq`、`unread_count`、`mention_unread`（展示用）。**禁止**客户端用 `max_seq - last_read_seq` 自行估算作为权威值。

**计入未读的消息**（同时满足）：

1. `status = NORMAL`（**撤回 RECALLED / 删除 DELETED 不计**；若已计入则撤回时对应未读/提及未读回退）
2. `sender_id ≠ 当前用户`
3. `seq > last_read_seq`

| 类型             | 规则                                                                                                                         |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **C2C / GROUP**  | 强成员离线持续累计；新消息满足上述条件则 `unread_count +1`；若 @我/`at_all` 则 `mention_unread +1`                           |
| **ROOM（在房）** | 同 C2C/GROUP 累计规则；打开房间并 `READ` 上报后：`last_read_seq = max_seq`，`unread_count=0`，`mention_unread=0`             |
| **ROOM（离房）** | **不再增加 `unread_count`**；仅当 @我或 `at_all` 时 `mention_unread +1`；列表优先展示「有人@我」红点                         |
| **重新进房**     | 进房成功：`last_read_seq = 当前 max_seq`，`unread_count=0`（`mention_unread` 清零或保留由产品固定为 **清零**）；避免历史洪水 |
| **免打扰**       | 计数仍更新，抑制强提醒与声音                                                                                                 |
| **已读上报**     | `READ { conversationId, seq }` 或 REST 等价接口：仅允许 `seq` 单调前进；服务端重算未读                                       |

展示约定：数字角标用 `unread_count`；若 `unread_count=0` 且 `mention_unread>0`，显示红点无数字。

### 4.4 消息能力

#### 4.4.0 发送主路径（先写后推，强制）

> **权威路径**：所有消息（含客户端经 WS 发起的发送）必须进入同一 `ImMessageService.send()`，**禁止**「只推送不落库」或「先广播再异步落库」。
> **WS 断开时仍允许 REST 发送**：落库成功即返回；对端在线则推送，不在线靠补洞。

**请求体（二选一目标）**：

```json
{
  "clientMsgId": "uuid",
  "msgType": "TEXT",
  "content": {},
  "conversationId": "已有会话ID，优先",
  "target": {
    "convType": "C2C",
    "bizId": "对方userId | groupId | roomId"
  }
}
```

| 规则                | 说明                                                                                                                                                                  |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 有 `conversationId` | 直接向该会话发；校验发送者是成员/有权                                                                                                                                 |
| 仅有 `target`       | 服务端 **upsert 会话**：C2C 按 `pair_key` 查找或创建并写入双方 `im_conversation_user`；GROUP/ROOM 校验已加入（或在房）后绑定已有会话，**不在发送时偷偷拉人进群/进房** |
| 首条 C2C            | 创建会话后 `max_seq` 从 1 开始分配本条消息                                                                                                                            |

```
发送方客户端
  │
  ├─ 主路径：POST /api/im/messages/send   ← WS 断线时仍可用
  │
  └─ 可选：WS 帧 { type:"SEND", requestId, payload: 同上 }
           └── Gateway 转调同一 ImMessageService.send()
                    │
                    ▼
         1) 鉴权 / 禁言 / 拉黑 / 频控 / 敏感词 / 陌生人策略
         2) 解析/创建会话（upsert）
         3) 事务内：分配 seq、INSERT im_message、
            更新 last_msg_* / max_seq、按 4.3.1 更新接收方未读
         4) 提交成功后 → Pub/Sub 发布 MESSAGE
         5) 仅向「已订阅该 conversationId」且在线路由命中的连接推送
         6) 返回：{ conversationId, msgId, seq, serverTime, status:"SUCCESS" }
```

| 规则       | 说明                                                    |
| ---------- | ------------------------------------------------------- |
| 失败不推   | 校验/落库失败 **不得** 广播                             |
| 幂等       | `(sender_id, client_msg_id)` 唯一；重复返回首次成功结果 |
| seq        | **仅服务端分配**                                        |
| 多实例     | Redis 会话锁或 DB 原子更新保证 seq                      |
| 与推送解耦 | 推送失败不影响落库成功；接收方 sync 补洞                |

#### 4.4.1 消息类型

| type   | 说明                                                                                                                     | 版本                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| TEXT   | 文本与系统 Emoji 面板（Unicode）；`@` 用 `atUserIds`/`atAll`，**不单列 msg_type**；自定义表情包 v1.1（CUSTOM/`STICKER`） | v1.0                       |
| IMAGE  | 图片，单张 ≤ 10MB，jpg/png/gif/webp                                                                                      | v1.0                       |

| VIDEO  | 短视频 ≤ 60s，≤ 50MB                                                                                                     | v1.2                       |
| FILE   | 文件 ≤ 50MB                                                                                                              | v1.2                       |
| CUSTOM | 系统通知/卡片/游戏/礼物等                                                                                                | v1.0 系统与卡片；礼物 v1.2 |
| TIP    | 灰字提示（进房、撤回提示、禁言提示）                                                                                     | v1.0                       |

### 4.5 群组与聊天室（统一模型）

#### 4.5.1 模型说明

> **统一容器思想**：`GROUP` 与 `ROOM` 均为「聊天目标（ChatTarget）」，共享成员角色与消息模型；差异在加入模式、成员持久化、历史漫游强度。

| 类型        | 编码      | 存储表     | 成员是否持久化                   | 历史漫游             | 典型人数   |
| ----------- | --------- | ---------- | -------------------------------- | -------------------- | ---------- |
| 私有群      | PRIVATE   | `im_group` | 是                               | 强                   | ≤ 200      |
| 公开群      | PUBLIC    | `im_group` | 是                               | 强                   | ≤ 2000     |
| 聊天室      | CHAT_ROOM | `im_room`  | **弱**：在线为主，可记 last_join | 近 N 天（默认 7 天） | 本期 ≤ 500 |
| 社群/直播群 | COMMUNITY | v1.2+      | 弱                               | 弱                   | 更大       |

关系：

```
im_conversation.conv_type = GROUP → im_group.group_id
im_conversation.conv_type = ROOM  → im_room.room_id
im_group_member / im_room_member 角色枚举一致：OWNER/ADMIN/MEMBER
```

#### 4.5.2 房间核心字段

| 字段           | 说明                             | 必填           |
| -------------- | -------------------------------- | -------------- |
| roomId         | 业务房间号                       | 是             |
| title          | ≤ 64                             | 是             |
| notice         | ≤ 500                            | 否             |
| categoryId     | 分类（含 CONFIDE 倾诉等）        | 是             |
| tags           | 1～5 个                          | 否             |
| cover          | 封面                             | 否             |
| joinMode       | FREE / APPROVE / INVITE          | 是             |
| speakMode      | ALL / ADMIN_ONLY / MUTE_ALL      | 是             |
| anonymousSpeak | 是否允许匿名发言                 | 否，默认 false |
| maxMembers     | 上限                             | 是             |
| status         | DRAFT / ACTIVE / CLOSED / BANNED | 是             |
| ownerId        | 房主                             | 是             |
| official       | 官方房                           | 否             |

群（`im_group`）额外字段：`groupType=PRIVATE|PUBLIC`，`joinMode` 对 PRIVATE 固定 INVITE。

#### 4.5.2.1 加入审批流（joinMode = APPROVE）

适用于 **公开群** 与 **joinMode=APPROVE 的房间**（私有群固定邀请制，不走本流）。

```
用户申请 --创建--> PENDING
PENDING --管理员/群主同意--> APPROVED（写入成员表并推送 MEMBER_JOIN）
PENDING --拒绝--> REJECTED
PENDING --申请人撤回--> CANCELLED
PENDING --超时（默认 7 天）--> EXPIRED
```

| 规则     | 说明                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------ |
| 申请频控 | 同一目标 24h 内仅 1 条有效 PENDING                                                               |
| 通知     | 新申请通知 OWNER/ADMIN；结果通知申请人（见 4.9）                                                 |
| 数据表   | `im_join_request`（target_type=GROUP/ROOM, target_id, applicant_id, status, handled_by, remark） |

```
DRAFT --发布--> ACTIVE
ACTIVE --关闭--> CLOSED
ACTIVE --违规封禁--> BANNED
CLOSED --重新开放--> ACTIVE
BANNED --解封--> ACTIVE（平台管理员）
```

#### 4.5.4 社群归属与同好聚集

| 能力       | 说明                      |
| ---------- | ------------------------- |
| 兴趣标签   | 用户 tags；大厅匹配       |
| 话题房     | 创建绑定 1～5 标签        |

#### 4.5.5 推荐排序（v1.0 可执行）

对候选房间计算：

```
score = 0.4 * norm(onlineCount)
      + 0.3 * norm(msgCount1h)
      + 0.2 * interestOverlap(user.tags, room.tags)
      + 0.1 * officialBoost
```

| 项                | 规则                                                          |
| ----------------- | ------------------------------------------------------------- |
| `norm`            | 分位归一到 0～1                                               |
| `interestOverlap` | Jaccard(user.tags, room.tags)                                 |
| `officialBoost`   | 官方房 = 1，否则 0                                            |
| 运营干预          | `system:chat:operate` 可配置 `manualWeight`（0～2）乘到总分   |
| 冷启动            | 无 tags 时按 online + msgCount1h；新房 24h 内给 0.05 探索加权 |

#### 4.10.1 指标看板

### 7.6 自研 WS 协议（事件载荷）

连接：`WSS /im/ws?ticket={wsTicket}`，Ticket 由 `/api/im/ws-ticket` 签发。

**客户端 → 服务端（上行）**

| type            | 说明                                                              |
| --------------- | ----------------------------------------------------------------- |
| `AUTH`          | 可选二次鉴权（若未走 query ticket）                               |
| `SUBSCRIBE`     | `{ conversationIds: string[] }` 订阅推送（单次 ≤100）             |
| `UNSUBSCRIBE`   | `{ conversationIds: string[] }` 退订                              |
| `SEND`          | 与 REST send 同 payload，走同一服务（可选；**WS 断线时用 REST**） |
| `READ`          | `{ conversationId, seq }`（seq 单调前进）                         |
| `PING`          | 连接心跳                                                          |
| `ROOM_PRESENCE` | `{ roomId }` 房间停留心跳                                         |

**服务端 → 客户端（下行）统一信封**

```json
{
  "event": "MESSAGE",
  "requestId": "可选，对应上行 SEND",
  "ts": 1730000000000,
  "data": {}
}
```

| event                                             | data 关键字段                                                                                                 |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `MESSAGE`                                         | `msgId, clientMsgId, conversationId, convType, senderId, msgType, content, seq, serverTime, atUserIds, atAll` |
| `RECALL`                                          | `msgId, conversationId, seq, operatorId`                                                                      |
| `READ`                                            | `conversationId, userId, seq`（单聊已读）                                                                     |
| `MEMBER_JOIN` / `MEMBER_LEAVE`                    | `targetType, targetId, userId, role?`                                                                         |
| `KICK` / `MUTE`                                   | `targetType, targetId, userId, muteUntil?, operatorId`                                                        |
| `ROOM_UPDATE` / `GROUP_UPDATE` / `PROFILE_UPDATE` | 对应实体补丁字段                                                                                              |
| `JOIN_REQUEST`                                    | `requestId, targetType, targetId, applicantId, status`                                                        |
| `IM_TAB_TAKEOVER`                                 | `{ fromTabId }`                                                                                               |
| `WS_DEGRADED`                                     | `{ reason }` 网关降级提示                                                                                     |
| `ACK`                                             | 上行 SEND/READ 的确认 `{ ok, errorCode?, msgId?, seq? }`                                                      |
| `PONG`                                            | 心跳响应                                                                                                      |

> `VITE_IM_MOCK=true` 时可用内存 Mock Gateway 联调，**仍须遵守先写后推语义**（Mock 也先假落库再推）。

## 八、非功能性需求

### 8.1 性能

| 项            | 指标                           |
| ------------- | ------------------------------ |
| 在线消息 E2E  | P95 ≤ 500ms（同城）；跨区 ≤ 1s |
| 会话列表首屏  | ≤ 1s（缓存命中）               |
| 历史/补洞分页 | ≤ 500ms（20 条）               |
| 大厅列表      | ≤ 800ms；分页或虚拟列表        |
| 消息流        | 虚拟滚动                       |

### 8.2 并发与可靠性

| 项         | 要求                           |
| ---------- | ------------------------------ |
| 单房间在线 | 本期 500                       |
| 重连       | 指数退避 + 补洞 + 发送队列幂等 |
| 投递       | 至少一次 + 客户端去重          |
| 写防重     | clientMsgId / requestId        |

### 8.3 兼容性

Chrome / Edge / Safari / Firefox 近两个正式版；桌面优先，房间页适配平板。

### 8.4 安全

鉴权、密钥隔离、XSS 默认文本渲染、上传校验、多级限流、管理查询审计；合规沿用平台策略。

### 8.5 可用性与可观测

监控连接成功率、发送失败率、重连次数、补洞耗时、seq 分配耗时；WS 网关故障时 REST 历史仍可用，提示 `IM_WS_DOWN` 并自动重连。

### 8.6 国际化

UI 文案走 i18n；消息内容本体不翻译（v2.0+ 插件）。
